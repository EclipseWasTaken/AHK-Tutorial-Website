Objects & Maps 🗺️

Hey! In this lesson, we will look at how to store structured data. While arrays (which we covered in our Fundamentals section) are great for simple ordered lists, Objects and Maps let you associate names directly with values. This is essential for storing configurations or mapping complex slot settings!

1. Objects vs. Maps: Which One Should You Use?

💡 My Rule of Thumb

In AHK v2, Objects and Maps look similar but have a huge internal difference:

  • Objects ({}): Great for static records or configs where keys are hardcoded variables. You access keys using dot notation (e.g. config.width).
  • Maps (Map()): Best for dynamic lists where keys are strings or numbers, and are added, checked, or removed dynamically. You access keys using bracket notation (e.g. myMap["key"]).

2. AutoHotkey Objects

Objects are extremely fast and lightweight. You define them using curly braces, and you can immediately read or write to their properties:

; Define a static configuration object
config := {
    width: 800,
    height: 600,
    title: "My Macro UI"
}

; Read properties
MsgBox("Window Size: " . config.width . "x" . config.height)

; Modify properties on the fly
config.title := "New Title"
MsgBox("App Title: " . config.title)

3. Key-Value Maps

Maps are proper hash tables. If you need to check if a key exists, delete keys, or loop through key-value pairs, always use a Map!

; Create a Map
userData := Map("name", "Eclipse", "role", "Admin")

; Insert or modify a key
userData["active"] := true
userData["city"] := "Delhi"

; Read keys (Note: brackets are mandatory!)
MsgBox("User Name: " . userData["name"])

; Check if a key exists before reading (crashes if key doesn't exist!)
if userData.Has("city") {
    MsgBox("User resides in: " . userData["city"])
}

; Delete a key
userData.Delete("role")

; Loop through all key-value pairs
for key, value in userData {
    MsgBox("Key: " . key . " ➜ Value: " . value)
}
