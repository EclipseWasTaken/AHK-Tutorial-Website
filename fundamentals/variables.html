Variables & Types 🧪

Hey! In this lesson, we will look at how AutoHotkey stores and manages data. Unlike strict languages like C++ or Java, AHK variables are dynamic—they can hold text, numbers, or complex objects, and you don't need to declare their types beforehand. However, this flexibility can lead to tricky bugs if you aren't careful!

1. Variables & Assignments

In AHK v2, you assign values using the := operator. The old = assignment from v1 is completely gone (it's now strictly used for comparisons). Strings must always be wrapped in quotes!

; Strings (single or double quotes work)
name := "Potato"
title := 'AHK Mentor'

; Numbers
age := 24
pi := 3.14159

; Hexadecimal numbers
hexVal := 0xFF ; Evaluates to 255

; Check if a variable has ever been assigned a value
if !IsSet(myMysteryVar) {
    MsgBox("myMysteryVar is currently empty/unassigned!")
}

2. Scoping Rules (Global vs. Local)

By default, variables created inside functions are local to that function. If you want to modify a global variable (created outside functions), you must explicitly declare it as global inside your function!

score := 0 ; Global variable

AddScore() {
    global score ; Declaring that we want to write to the global score variable
    score += 10
}

ShowScore() {
    ; We can read global variables without the global keyword, but declaring local helps organize
    local message := "Your current score: " . score
    MsgBox(message)
}

^1:: AddScore()
^2:: ShowScore()

3. Type Conversion & Checking (The Beginner Trap!)

⚠️ The Silent Type Bug

A major trap for beginners is comparing strings to numbers. In AHK v2, "42" == 42 is **false**! If you read a number from a text file, an input box, or the clipboard, it is treated as a String, and comparing it to a raw number will fail silently.

The Solution: Use type conversions to ensure clean matching!

; Reading from a dialog returns a String!
input := InputBox("Enter a number:", "Guesser")

if (input.Result != "Cancel") {
    ; Convert string to integer explicitly so comparisons work!
    numberVal := Integer(input.Value)
    
    if (numberVal == 42) {
        MsgBox("You guessed the secret number!")
    } else {
        MsgBox("Nope, " . numberVal . " is not it.")
    }
}

4. Built-in Type & Checking Functions

Here are the built-in functions I use to inspect variables and verify inputs before using them in my automation scripts:

Function What it returns / checks Examples
Type(val) Returns the type as a string: "Integer", "Float", "String", "Array", "Map", etc. Type(3.14) ➜ "Float"
IsInteger(val) Returns true if the value can be parsed as an integer. IsInteger("42") ➜ true
IsFloat(val) Returns true if the value is a floating-point number. IsFloat(3.14) ➜ true
IsNumber(val) Returns true if the value is either an integer or float. IsNumber("15.5") ➜ true
Integer(val) Converts/coerces the value to an integer. Integer("100") ➜ 100
Float(val) Converts/coerces the value to a floating-point decimal. Float("2.5") ➜ 2.5
String(val) Converts/coerces a number or boolean to a standard string. String(true) ➜ "1"
