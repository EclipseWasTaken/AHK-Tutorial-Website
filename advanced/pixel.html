While Loops With Pixel Conditions

In real automation, you rarely want while true. Instead, you loop based on a pixel condition — whether something has appeared or disappeared on screen. This is how most real scripts actually work.

Advanced

Pattern 1 — Wait Until Pixel Appears

Use this when you are waiting for something to show up on screen before acting.

; We keep looping while the red pixel is NOT found
; Once it appears, the loop exits and we click

While !PixelSearch(&x, &y, 0, 0, A_ScreenWidth, A_ScreenHeight, 0xFF0000, 5)
{
    Sleep(50)   ; Check every 50ms — don't hammer the CPU
}

Click(x, y)  ; Now click where we found it
🔍 What this means, step by step

PixelSearch returns true when the pixel is found. So !PixelSearch(...) is true while the pixel is absent. The loop keeps sleeping and retrying. The moment the pixel appears, PixelSearch returns true, the ! flips it to false, and the loop exits — then we click.

Pattern 2 — Keep Acting While Pixel Exists

Use this when you want to keep doing something until a pixel disappears.

; Keep clicking while the green "Start" pixel is still visible
While PixelSearch(&x, &y, 0, 0, A_ScreenWidth, A_ScreenHeight, 0x00FF00, 5)
{
    Click(x, y)
    Sleep(100)  ; Pause between clicks
}
🔍 What this means, step by step

When PixelSearch finds the pixel it returns true, so the loop body runs. We click, sleep, and check again. The moment the pixel disappears, PixelSearch returns false and the loop stops immediately.

The Two Core Patterns

while !condition → Wait until something appears
while condition → Keep going until something disappears

Everything in pixel-based automation is built from these two ideas.

PixelSearch Parameters

ParameterWhat it is
&x, &yOutput vars that receive the found pixel's coordinates
x1, y1Top-left corner of search area (use 0, 0 for full screen)
x2, y2Bottom-right corner (A_ScreenWidth, A_ScreenHeight)
0xFF0000Target color in hex RGB format
5Color variance tolerance (0 = exact match, higher = more lenient)

Real-World Example: Wait for Button, Then Click

#Requires AutoHotkey >= 2.0
#SingleInstance Force

^F1::
{
    ; Step 1: First, we wait for the "Start" button pixel to appear
    ToolTip("Waiting for button...")
    While !PixelSearch(&x, &y, 0, 0, A_ScreenWidth, A_ScreenHeight, 0x00B050, 10)
    {
        Sleep(100)
    }

    ; Step 2: Button found — click it
    ToolTip("Found! Clicking...")
    Click(x, y)
    Sleep(500)

    ; Step 3: Wait for it to go away (confirm click worked)
    While PixelSearch(&x, &y, 0, 0, A_ScreenWidth, A_ScreenHeight, 0x00B050, 10)
    {
        Sleep(50)
    }

    ToolTip("Done!")
    Sleep(1500)
    ToolTip()
}

Practice Problems

🟢 A "Start" button appears on screen

→ Use while !PixelSearch(...) — loop until it shows up, then click it.

⏳ A loading spinner is spinning

→ Use while PixelSearch(...) — keep waiting while it exists, exit when it's gone.

🔴 A "Stop" signal disappears

→ Use while PixelSearch(...) — loop while stop signal exists; when it goes, proceed.

✨ A confirm dialog appears

→ Use while !PixelSearch(...) — wait until dialog pixel appears, then interact.

⚠️ Pixel Search Limitations

Pixel-based loops are powerful but fragile. Colors can shift slightly due to anti-aliasing or rendering differences. Screen resolution and DPI settings affect coordinates. UI elements can move between resolutions. For production scripts, combine pixel search with image search, add retry counters, and always include a timeout so you don't loop forever if the pixel never appears.

Adding a Timeout (Best Practice)

; Safe pixel wait with timeout
startTime := A_TickCount
timeout   := 10000  ; 10 seconds max

While !PixelSearch(&x, &y, 0, 0, A_ScreenWidth, A_ScreenHeight, 0xFF0000, 5)
{
    if (A_TickCount - startTime > timeout) {
        MsgBox("Pixel never appeared! Aborting.")
        return
    }
    Sleep(50)
}

Click(x, y)  ; Safe to act now
